📤 Transactional Outbox

📅 2026-06-23 · không mất event giữa commit DB ↔ publish Kafka · trả nợ SP3/SP4 (kyc.revoked) · at-least-once + consumer idempotent (D9)

1.Vấn đề: dual-write — hai thứ tự cùng hỏng

kyc revoke = save DB + send Kafka. Hai hệ thống, không transaction chung.

2.Outbox: ghi event vào DB cùng transaction

flowchart TB
    subgraph TX["① TRANSACTION nghiệp vụ (MỘT DB, MỘT tx — NGUYÊN TỬ)"]
        S1["UPDATE kyc_case = REVOKED"]
        S2["INSERT outbox(topic=kyc.revoked, payload, PENDING)"]
    end
    TX -->|commit cả hai hoặc không cả hai| OK["khe dual-write BỊ BỊT"]
    OK --> R["② Relay @Scheduled: outbox WHERE PENDING → Kafka → mark SENT"]
    R --> K[("Kafka kyc.revoked")]
    K --> W["wallet consumer (idempotent D9)"]
    R --> P["③ Purge: xoá SENT cũ > TTL (như SP7)"]
Mấu chốt: event giờ nguyên tử với nghiệp vụ vì cả hai là ghi vào CÙNG một DB trong CÙNG một tx. Crash sau commit → event vẫn nằm trong bảng outbox → relay đẩy sau → KHÔNG mất.

3.At-least-once + consumer idempotent (O3, O4)

sequenceDiagram
    autonumber
    participant R as Relay
    participant K as Kafka
    participant DB as outbox
    R->>K: send kyc.revoked ✓
    Note over R: 💥 crash TRƯỚC khi mark SENT
    Note over DB: row vẫn PENDING
    R->>DB: (chạy lại) đọc PENDING → send LẦN NỮA
    R->>K: kyc.revoked (TRÙNG)
    K->>K: wallet consumer evict cache 2 lần — VÔ HẠI (D9)
Đổi "mất" thành "trùng": relay vẫn dual-write (send rồi mark) → at-least-once. Trùng vô hại NẾU consumer idempotent — wallet đã idempotent tự nhiên (D9). → mọi consumer tương lai BẮT BUỘC idempotent (điều kiện đứng của outbox).

4.Quyết định O1–O8

#Quyết địnhLý do
O1Ghi event vào bảng outbox trong CÙNG tx nghiệp vụREVOKED + outbox = 1 DB 1 tx → nguyên tử; bịt dual-write
O2Relay riêng: outbox PENDING → Kafka → mark SENTKafka ngoài DB, cần tiến trình đẩy
O3At-least-once (relay crash → gửi lại → trùng)thà trùng còn hơn mất
O4Consumer BẮT BUỘC idempotent (D9 sẵn)trùng chỉ vô hại khi idempotent
O5Purge SENT cũ > TTLbảng outbox không phình vô hạn (như SP7)
O6Polling Publisher mặc định; CDC (Debezium) là nâng cấppolling đơn giản; CDC = hạ tầng SP7-OLAP
O7Giữ thứ tự: poll theo id; Kafka key=userIdAPPROVED phải trước REVOKED cùng user
O8Áp kyc trước; wallet multi-tenant → relay fleet per-schemabắt đầu ở nơi nợ thật
